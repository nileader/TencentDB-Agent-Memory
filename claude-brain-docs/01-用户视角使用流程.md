# Claude Code 人脑式知识库 —— 用户视角使用流程

> 目标：让 Claude Code 像你的「第二大脑」——干活时自己想起相关知识，不用你每次手动喂资料。
> 适用：你（银时）+ 要借鉴的同事。本文只讲「用起来什么感觉」，不讲安装。
>
> 安装文档：
> - qmd 侧：`qmd搭建-操作手册.md`
> - TencentDB Agent Memory（`claude-mem` 命令）侧：`tencentdb-agent-memory/tencentdb-agent-memory搭建 - 操作手册.md`

---

## 核心心智模型：它像人脑的哪部分

你的大脑记东西分几层，这套系统一一对应：

| 人脑 | 系统 | 作用 | 覆盖命令 |
|---|---|---|---|
| 「这事我以前和 AI 聊过，大概记得结论」 | **TencentDB Agent Memory**（L0/L1/L2/L3 四级） | 对话沉淀，自动抽取、跨 session 自动召回 | 仅 `claude-mem` |
| 「具体细节我得翻当时的笔记」 | **qmd 知识库** | 你手写的 md 笔记原文，按需下钻到具体段落 | 主 `claude` + `claude-mem` |
| 「我的为人处世原则」 | **CLAUDE.md 常驻层** | 你的身份、原则、工作习惯，每次开工就在脑里 | 主 `claude` + `claude-mem` |
| 「已经确认过要记的规则」 | **Claude Code auto-memory** | Claude 主动问你 yes/no 后才写入，跨 session 自动加载索引 | 主 `claude` + `claude-mem` |

**一句话**：TencentDB 负责「想起旧对话」，qmd 负责「翻笔记」，CLAUDE.md 负责「我是谁」，auto-memory 负责「记住已确认的规则」。

**两个命令的差别**：
- 主 `claude` → 走 ducky，是生命线；**不使用 TencentDB**，跨 session 对话记忆仅靠 auto-memory
- `claude-mem` → 走 MemoryProxy；**启用 TencentDB**，全自动跨 session 沉淀+召回

## 一、首次用之前：你只做一次的事

1. 把你的两个 md 目录绑进 qmd（一次性）：
   - `~/workspace/work-context`
   - `~/workspace/work-agent/work-note`
2. （可选）搭 TencentDB Agent Memory 栈，让 `claude-mem` 命令跑起来。
3. 在 `~/.claude/CLAUDE.md` 写一条「召回规约」：遇到陌生主题先翻笔记，学新规则前先问。

之后每次用，你什么都不用做——下面是日常。

## 二、日常使用流程（一步一步，你能感知的视角）

### 场景 A：主 `claude` 命令下问一个偏具体、需要翻笔记的问题

#### Step 1 · 你发话
> 「帮我回顾下之前调研本地知识库工具的结论」

#### Step 2 · Claude 调 qmd 翻笔记
- Claude 觉得答案在你自己的笔记里，调 `qmd query "本地知识库 选型"`
- 拿回几篇笔记段落，带路径和相关度分

#### Step 3 · Claude 综合回答
- 引用你笔记里的原话给结论，而不是泛泛答案

#### Step 4 · 有新结论要记？先问你
- Claude 提议：「要把『XX』写进 auto-memory 吗？」
- 你 yes/no 掌握开关

### 场景 B：`claude-mem` 命令下问一个「以前聊过」的问题

#### Step 1 · 你在新 session 里发话
> 「上次我们讨论的那个方案边界条件是啥来着？」

#### Step 2 · TencentDB 自动召回
- 新 session 启动时，TencentDB L1/L2 已经把和当前话题相关的历史对话结论**注入到 Claude 的上下文**
- 你没打招呼，Claude 已经知道「上次」指的是啥

#### Step 3 · 结合 qmd 拉笔记原文（如需要）
- 若历史结论指向某篇 md，Claude 追加调 `qmd query` 拿具体段落
- 两条通路接力，不重复

#### Step 4 · 你说话时冒出的新偏好会**自动沉淀**
- TencentDB 后台异步抽取 L0（原始对话）→ L1（原子卡片）→ L2（场景）→ L3（长期画像）
- **不需要**你说「记住这条」——它自己抽

## 三、你能感知的三个「它懂我」瞬间

1. **不用重复强调偏好**：你说过的「star≥10k」「数据在本地」「不切 provider」，在 `claude-mem` 下会自动跨 session 命中；在主 `claude` 下需要靠 auto-memory 显式沉淀。
2. **它会引用你的旧笔记**：回答里出现「你自己 X 月写的笔记里说过……」，不是泛泛的网搜。
3. **它越用越懂**（仅 `claude-mem`）：每次对话结束后台自动抽取新记忆，下次召回更贴你。

---

## 四、什么时候用哪个命令

| 场景 | 推荐命令 | 原因 |
|---|---|---|
| 日常写代码、写文档、写脚本、单次执行 | 主 `claude` | 生命线稳定；单次任务不依赖历史对话 |
| 跨 session 沉淀有价值的偏好/结论 | `claude-mem` | 自动沉淀闭环，无需手动 remember |
| 遇到 `claude-mem` 或 MemoryProxy 故障 | 主 `claude` 兜底 | 主 claude 永远不受 TencentDB 栈影响 |
| 翻自己写的笔记 | 都行 | qmd 在两个命令下都可用 |

---

## 五、你得管的：记忆卫生

三层都要定期检查（月度即可）：

- **qmd**：`qmd update && qmd embed`（增量摄入新笔记），`qmd status`（看索引健康）
- **TencentDB**：让 `claude-mem` 里的 agent 帮你跑一遍矛盾/过期检查
- **auto-memory**：让 Claude 在月初提醒你翻一次 `~/.claude/projects/-home-admin/memory/`，删过期条目

**陈旧记忆比没有更糟**——这是社区公认的最大坑，也是你个人反复强调的。

---

## 六、和传统 RAG 的区别（给同事讲时的关键点）

| | 传统 RAG | 这套人脑式 |
|---|---|---|
| 召回触发 | 你主动问 | agent 干活时自动想起 + session 启动自动注入 |
| 存什么 | 文档切片 | 文档原文 + 对话原文 + 原子卡片 + 场景 + 画像 |
| 跨项目 | 无 | 有（TencentDB 全局 user 记忆，qmd 全局 collection） |
| 越用越懂 | 否（每次从零） | 是（TencentDB 后台异步抽取，记忆复利） |
| 写回 | 否 | 有（`claude-mem` 自动沉淀，主 `claude` + auto-memory 需 yes/no） |
