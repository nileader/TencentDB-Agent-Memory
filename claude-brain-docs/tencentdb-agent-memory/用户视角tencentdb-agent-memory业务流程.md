# TencentDB Agent Memory —— 用户视角业务流程

> 目标：给 Claude Code 造一个**自动沉淀、跨项目、跨会话**的「第二大脑」——它一边干活一边自己把该记的记下来，换个项目、隔几天再开新会话，它依然记得你是谁、你的偏好、你们之前聊过什么。
> 适用：你（银时）+ 要借鉴的同事。本文只讲「用起来什么感觉、数据怎么流」，**不讲安装**（安装见 `tencentdb-agent-memory搭建 - 操作手册.md`）。
> 全文结论均来自本机 POC 实测跑通（详见「补充说明」）。

---

## 一、为什么是它：CC 原生记忆的天花板

Claude Code 自带记忆（`CLAUDE.md` / 项目内 memory），但它有一条硬天花板：**不能跨项目**。你在项目 A 里教它的偏好，换到项目 B 就白纸一张，每个新工程都要重新交代一遍「我只有 idealab 一个 key，别建议我切 provider」。

TencentDB Agent Memory 补的就是这块——它把记忆做成**独立于任何单个工程的一层服务**，用「代理转发」的方式挂在 CC 和上游大模型之间。你正常聊天，它在旁边默默：
- **自动沉淀**：不用你手动喊「记住这个」，它自己从对话里抽事实、攒画像；
- **跨项目召回**：你的全局偏好绑在你的身份上，任何项目开新会话都能想起；
- **零代码接入**：不装插件、不写 MCP，只把 CC 的 API 地址指向代理即可。

一句话：**CC 原生记忆是「这个项目的便签」，TencentDB 是「跟着你走的那颗脑子」。**

## 二、核心心智模型：像人脑一样分四层沉淀

人脑不会把每句话都原样背下来，而是层层压缩：先记流水（今天聊了啥）→ 提炼成知识点（他这人有个规矩）→ 归纳成场景经验 → 最后沉淀为对一个人的整体印象。这套系统就是这么设计的，四层金字塔（L0→L3）：

| 层 | 名字 | 人脑类比 | 存什么 | 怎么产生 |
|---|---|---|---|---|
| **L0** | Conversation | 「今天的流水账」 | 原始对话逐轮 | 每轮**同步**落盘 |
| **L1** | Atom 原子记忆 | 「记住的知识点」 | 一条条独立事实（偏好/事件/指令） | 后台**异步**抽取（攒够几轮触发） |
| **L2** | Scenario 场景 | 「这类事我有经验」 | 把相关原子归纳成场景 | 后台异步，L1 之后延迟触发 |
| **L3** | Persona 人格画像 | 「我对这个人的整体印象」 | 用户叙事画像 + 核心原型 | 攒够 N 条新记忆后生成 |

**关键差异化能力（cognee 那套缺的）：整条 L0→L1→L2→L3 全自动、全后台、无需手动 `remember`。** 你只管聊，金字塔自己往上长。

> 实测举例：POC 里我只跟它说了两句偏好，它就自动抽出了准确的原子——
> - instruction：「用户（银时）要求 AI 不要建议其切换 provider」
> - persona：「用户（银时）叫银时，且只有 idealab 一个 key」
> 全对，没有一句是我手动喊它记的。

## 三、一次请求的完整业务流程（数据怎么流）

假设你已把 CC 指向了代理，下面是你发一句话时，背后发生的事：

```
你(CC) ──①带记忆身份的请求──▶ MemoryProxy(代理) ──②透传──▶ 上游大模型(ducky)
                                    │                              │
                                    │③注入历史记忆到system          │④正常回答
                                    │⑤把这轮对话沉淀给 MemoryCore    │
                                    ▼                              ▼
                              MemoryCore(记忆内核) ◀──────────── 回答返回给你
                                    │
                                    ⑥后台异步：L0→L1→L2→L3 层层提炼
```

**Step 1 · 你发话**：CC 把请求发给代理（不是直连大模型了），请求里带着你的身份（team/user/agent/session）。

**Step 2 · 透传上游**：代理把你的请求**原样透传**给上游大模型（你的 ducky Bearer 令牌一字不改地带过去），大模型该怎么答还怎么答——**你的主链路体验不变、不降智**。

**Step 3 · 注入历史记忆（召回）**：在转发之前，代理去 MemoryCore 捞你的历史画像，**注入进这次请求的 system 提示里**。于是大模型这一轮就「带着对你的记忆」在回答。

**Step 4 · 大模型正常回答**：上游返回答案，代理原样回给你的 CC。

**Step 5 · 沉淀这轮对话**：代理把「你问 + 它答」这轮对话喂给 MemoryCore 存成 L0。

**Step 6 · 后台层层提炼**：MemoryCore 在后台异步地把 L0 攒够几轮 → 抽成 L1 原子 → 归纳成 L2 场景 → 攒够了升成 L3 人格。**全程你无感，不阻塞你的对话。**

## 四、跨会话/跨项目「一直记得」是怎么做到的

### 身份 = 记忆的命名空间
每条记忆都挂在一组身份上：`team_id / user_id / agent_id`。只要你换项目、换会话时用的是**同一组身份**，捞出来的就是同一颗脑子的记忆。POC 实测：全新会话捞记忆，返回的原子全部正确归属到同一个 `user`，包括**上一轮对话刚沉淀出来的那条**——说明「记」和「跨会话读」是通的。

### 两条召回通道（这版的重要设计）
这版**故意不再每轮都把所有记忆塞进上下文**（那样会撑爆 KV cache、拖慢每一轮）。改成粗细分离的**混合召回**：

| 通道 | 召回什么 | 时机 | 你的感知 |
|---|---|---|---|
| **被动·自动注入** | L3 人格画像 + L2 场景索引 | **每会话自动**进 system | 无感、零成本，一开口它就懂你是谁 |
| **主动·按需检索** | L0/L1 细粒度原始记忆 | 模型**自己判断需要时**调工具去捞 | 像人「我翻一下当时记录」——用到才捞 |

→ 所以「它懂我」分两个粒度：**对你的整体印象随时在线**（L3 进 system），**具体某件事的细节按需现捞**（L1 走工具）。这比「每轮全量灌」更省 token、更健康。

> 实测：全新会话发一句「建议我换 provider 吗」，转发到上游的请求体从 154 字节涨到 10921 字节，system 里自动多了一块 `<tdai_profile_memory>`，里面是「银时」「idealab」「不要建议切换」等历史画像——**这个新会话从没提过这些，是 L3 被自动注进来的**。

## 五、你能感知的三个「它懂我」瞬间

1. **换项目不用重新自我介绍**：项目 A 教过的偏好，项目 B 开新会话它自己就带着——因为记忆挂在你身上，不挂在工程里。
2. **不用手动喊「记住」**：正常聊，该沉淀的它后台自己抽。你甚至不知道它什么时候记的，下次就用上了。
3. **越用越准**：每轮对话都在喂 L0，后台持续把新事实提炼进 L1/L3，画像随时间越来越贴你。

## 六、你得管的：记忆卫生

自动沉淀是双刃剑——它也会记进**过期或猜错**的东西。所以要定期（比如每月）做一次记忆卫生：
- 让 Claude 查一遍原子记忆里有没有矛盾、过期、猜测性内容；
- 删掉不对的（**陈旧记忆比没有更糟**，这是这类系统公认最大的坑）；
- POC 提炼脑偶尔会抽出「用户姓名未知」这类模糊原子（同一件事另一轮的抽取），需要人工核对合并。

> 用 `read-local-memory` 工具（MemoryCore 自带的 bin）可以直接把本地沉淀的记忆导出来人工核对，见操作手册。

## 七、和 CC 原生记忆 / 传统 RAG 的区别（给同事讲的关键点）

| | CC 原生记忆 | 传统 RAG | TencentDB Agent Memory |
|---|---|---|---|
| 跨项目 | ❌ 不能 | 看实现 | ✅ 绑身份、跟人走 |
| 自动沉淀 | 半自动（要写 CLAUDE.md） | ❌ 只读 | ✅ L0→L3 全自动后台 |
| 召回触发 | 常驻全量 | 你主动查 | 混合：画像自动注入 + 细节按需检索 |
| 接入成本 | 原生 | 要建索引管道 | ✅ 改个 API 地址，零代码 |
| 越用越懂 | 有限 | ❌ 每次从零 | ✅ 记忆复利 |
| KV cache 友好 | — | — | ✅ 故意不每轮全量灌 |

## 八、当前状态与边界（诚实说明）

- **技术验证 = 通过**：转发、自动沉淀、跨会话召回注入，全部本机实测跑通，主 CC 全程零改动。
- **本 POC 用 mock 上游验证**（避免动 ducky）；真接你的 CC 时上游换成 ducky，代理已实测能把你的 Bearer 原样透传，**不需要改一行源码**（config-only）。
- **接入主 CC 是一次「换 API 地址」的可逆操作**，但会碰到路由/环境变量，需按操作手册的「可逆切换」章节谨慎做，并保留原 ducky 直连作为随时可回退的生命线。
