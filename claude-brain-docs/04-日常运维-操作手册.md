## 1. 加了新笔记 —— qmd 自动增量（默认托管） ★最常用

**默认由守护进程每 30 分钟自动跑一次 `qmd update && qmd embed`**，无需手动干预。守护脚本落在 `~/workspace/common-toolkit/ai/memory/qmd/`（与 TDAI 栈完全独立）。

### 1.1 守护进程起停/查看

```sh
# 启动（幂等，已在跑则打印现有 pid）
~/workspace/common-toolkit/ai/memory/qmd/qmd-auto-start.sh

# 查状态 + 最近 20 行日志
~/workspace/common-toolkit/ai/memory/qmd/qmd-auto-status.sh

# 停
~/workspace/common-toolkit/ai/memory/qmd/qmd-auto-stop.sh

# 改间隔（默认 1800s）
QMD_INTERVAL=3600 ~/workspace/common-toolkit/ai/memory/qmd/qmd-auto-start.sh
```

日志：`~/workspace/common-toolkit/ai/memory/qmd/qmd-auto.log`

设计要点见 `~/workspace/common-toolkit/ai/memory/qmd/README.md`。

### 1.2 手动增量（守护挂了 / 想立刻生效）

推荐用一次性脚本（与守护共用 flock，避免同时改索引）：

```sh
~/workspace/common-toolkit/ai/memory/qmd/qmd-auto-start-1-time.sh
```

裸命令等价：
```sh
qmd update && qmd embed
```
- `qmd update`：重建文本索引（BM25，不走外网）。
- `qmd embed`：给新增内容生成向量（本地 GGUF 模型，秒级）。
- 增量语义：旧文件秒跳过，只处理新增/改动/删除。删除的文件会**同步从索引清掉**。

### 1.3 验证摄入生效
```sh
qmd query "随便一句新笔记里的话" -n 3        # 能命中新笔记 = 生效
qmd status                                    # Documents Total 应对得上目录里 md 总数
```

> ⚠️ **守护挂了会怎样**：新笔记要等到手动跑或守护恢复才被搜到。用 `qmd-auto-status.sh` 每周瞄一眼。

> **TencentDB 侧**：它不索引 md 目录，只沉淀你和 `claude-mem` 的对话。新笔记进 qmd 就够了，不需要单独喂给 TencentDB。

## 2. 交互中沉淀的记忆存到哪 —— 三处并存

平时在 claude / claude-mem 里聊出来的心得/结论，会落到不同位置。搞清楚才知道去哪找、怎么改。

| | ① Claude Code auto-memory | ② TencentDB Agent Memory |
|---|---|---|
| **触发命令** | 主 `claude` + `claude-mem` 都会写 | 仅 `claude-mem` 会写 |
| **谁触发** | agent 判断值得长期记就写（会视情况问你 yes/no） | `claude-mem` 会话结束后**自动异步抽取**，无需你确认 |
| **存到哪** | `~/.claude/projects/-home-admin/memory/<名字>.md`，一条一个 md 文件；索引在同目录 `MEMORY.md` | TencentDB 云端（MemoryProxy 转发），本机 `~/.tdai-lab/data/` 有本地拷贝 |
| **形式** | 纯文本 md，**你能直接打开看/手改** | 结构化：L0 原始对话 / L1 原子卡片 / L2 场景 / L3 长期画像 |
| **怎么被想起** | 每次开会话**自动载入** `MEMORY.md` 索引到上下文 | 每次 `claude-mem` 新 session 启动**自动召回并注入上下文** |

**一句话定位「这条心得在哪」：**
- 走 **①** → `~/.claude/projects/-home-admin/memory/` 下一个个 `.md`（如 `no-provider-switch.md`），`MEMORY.md` 是目录索引。**可直接编辑**。
- 走 **②** → 靠 `claude-mem` 会话自动召回；要人工核对可用 TencentDB 手册里的 `read-local-memory` bin。

> ⚠️ **两套并存不冲突**：主 `claude` 命令下只有 ①；`claude-mem` 命令下 ①+② 都在。同一条偏好可能两边都存，冗余但安全。

## 3. 日常召回是怎么发生的（无需你操作）

### 主 `claude` 命令下
- **CLAUDE.md 「知识召回规约」** 每次开会话自动载入 → agent 干活时**按需**调 `qmd query`（翻笔记原文）
- **auto-memory `MEMORY.md`** 自动载入到上下文，agent 依据里面索引条目决定是否深入读某条 memory 文件

### `claude-mem` 命令下
- 上面这套照旧
- **额外**：TencentDB 在 session 启动时把与当前会话主题相关的 L1/L2 卡片**自动注入上下文**——你不用问，Claude 就已经知道你之前说过啥
- 后台异步：本次会话结束后 5~600s 内，TencentDB 自动把新对话抽成新的 L0/L1/L2 卡片

### （默认不配）UserPromptSubmit Hook
每次发话同步阻塞跑 qmd（即便 `--no-rerank` 也 ~4.5s），多数发话用不上召回 = 高频白付、拖慢交互。要「发话即自动撒网」再配且必带 `--no-rerank`（见 `qmd搭建-操作手册.md` §4 / 补充 §11）。

## 4. 快速健康检查（怀疑不工作时跑）

```sh
# qmd
qmd query "本地知识库" -n 3        # 能返回带路径的片段 = 知识库层 OK
qmd status                          # 看索引大小、文档数、collection

# MCP 层
claude mcp list                     # 应见 qmd ✓ Connected

# TencentDB 栈（如启用 claude-mem）
~/.tdai-lab/status-all.sh          # MemoryCore + MemoryProxy 应双 UP
```

**常见故障**：
- qmd 报 `no embeddings` → 补跑 `qmd embed`
- MCP 里没 qmd → 重装 `claude plugin install qmd@qmd`，重启会话
- `claude-mem` 报 `Failed to parse JSON` / `Extra inputs are not permitted` / 401 → 见 TencentDB 手册 §7.8 故障诊断四步；一键 patch 用 `~/.tdai-lab/apply-proxy-patches.sh`

## 5. 记忆卫生（每月）

三处都要过一遍：

- **auto-memory**：
  - 删单条 → 直接删 `~/.claude/projects/-home-admin/memory/<名字>.md` 并从 `MEMORY.md` 去掉那行
  - 让 agent 月初按 CLAUDE.md 规约提醒你查矛盾/过期/孤儿

- **qmd**：
  - 改笔记后跑 `qmd update && qmd embed`
  - `qmd status` 看索引是否健康

- **TencentDB**（`claude-mem` 侧）：
  - 让 `claude-mem` 里的 agent 帮你跑一遍矛盾/过期检查
  - 具体操作见 TencentDB 手册对应章节

**陈旧记忆比没有更糟**——这是社区公认的最大坑。
